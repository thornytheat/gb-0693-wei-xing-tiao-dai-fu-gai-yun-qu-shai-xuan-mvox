# 数据定义

目标经度区间支持跨180度拆分；覆盖只算并集，云掩膜从有效条带扣除，重复条带不增加面积。

输入字段：scene, alias, west, east, cloud_w, cloud_e, quality, price, captured, version。所有ID按字符串保留；空字符串、NULL、N/A、未知与“-”视为缺失，不能当作数值零。数值使用Decimal，输出为十进制字符串。重复业务键相同内容计重复，内容冲突隔离或按明确修订号裁决，不按文件顺序盲目覆盖。

每条证据有原始行号，隔离记录有原因码及原值。时间区间使用半开边界；日期定义在各模块规则内显式声明。输入表头可调序，不得缺列或重复；中文旧编码可上传。规则版本存入运行清单，重跑使用原始文件内容摘要与规则版本共同确定幂等键。复核使用revision乐观锁，陈旧提交返回409。

固定纬带目标为[170,180)与[-180,-170)，只衡量经度覆盖宽度，不宣称球面面积。经度相同端点拒绝，避免无法区分全世界与空条带。采购使用预算1000 CNY的确定性边际覆盖/价格贪心，并非全局最优证明；同分按场景编号排序。完整交付仍以区间并集核验。

## 多过境融合（M8）

同一场景（canonical）可保留多次过境观测：M2在既有“只采信最新版本”裁决不变的前提下，额外保留同场景全部结构有效过境供M8复核。M8按“最新过境优先、版本降序、行号升序”的确定性顺序，将各过境目标纬带内的清晰段切分为互不重叠的融合段，每一段只归属一个来源观测，并记录来源场景、原始行号、版本、采集时间与角色（基线/补充）。

融合是提案而非自动生效：确认前M4覆盖、M5缺口、M6采购一律保持基线口径。仅当人工在M8点击“确认融合”后，系统才在单事务内重算融合口径的缺口与采购，结果存入confirmed视图；点击“退回”则提案作废、基线不变。

未融合记录逐条给出原因码：`FUSE_BASELINE`（最新过境，作基线采信）、`FUSE_REDUNDANT`（清晰段与已融合覆盖完全重叠，无独有补充）、`FUSE_CLOUD`（目标纬带内无清晰段）、`FUSE_QUALITY`（质量未通过）、`FUSE_SUPERSEDED`（旧版本被更新过境覆盖）。M2隔离的`SUPERSEDED`记录仍保留在隔离区，M8未融合表只统计结构有效但未贡献独有段的过境。

采购台账（purchase_ledger）以(run_id, 场景)为唯一键：一个场景无论融合了几个过境，采购只计一次；同批次重试受revision乐观锁与唯一键双重约束，不新增采购。重算或写入中断时事务整体回滚，批次恢复到确认前的旧版本（revision、fusion_status、confirmed视图、台账均不变）。
